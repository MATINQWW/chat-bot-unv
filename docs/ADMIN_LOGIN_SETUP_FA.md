# راه‌اندازی پنل امن نوکا — نسخه 1.6.15

این نسخه پنل `/admin` را به آمار واقعی Redis، گزارش‌های تجمیعی و فایل پایگاه دانش متصل می‌کند. ورود و مدیریت حساب‌ها در سرور انجام می‌شود.

## ۱) پیش‌نیاز Redis

در Environment Variables پروژه Vercel، این دو متغیر در Production باید وجود داشته باشند و توکن دسترسی خواندن/نوشتن داشته باشد:

- `KV_REST_API_URL`
- `KV_REST_API_TOKEN`

توکن فقط‌خواندنی برای نشست و مدیریت ادمین کافی نیست.

## ۲) ساخت رمز مدیر اصلی

در پوشه پروژه اجرا کنید:

```bash
node scripts/hash-admin-password.js
```

رمز را دو بار وارد کنید. حداقل ۱۲ نویسه لازم است. خروجی `scrypt$...` را کپی کنید؛ رمز خام نمایش داده نمی‌شود.

## ۳) متغیرهای Production

فقط حساب مدیر اصلی را در Vercel تعریف کنید:

| نام متغیر | مقدار |
|---|---|
| `NOOKA_SUPERADMIN_EMAIL` | ایمیل مدیر اصلی |
| `NOOKA_SUPERADMIN_PASSWORD_HASH` | خروجی scrypt |
| `NOOKA_SUPERADMIN_NAME` | نام نمایشی (اختیاری) |
| `KV_REST_API_URL` | آدرس Redis |
| `KV_REST_API_TOKEN` | توکن Redis با دسترسی خواندن/نوشتن |

متغیرهای قدیمی `NOOKA_ADMIN_EMAIL`، `NOOKA_ADMIN_PASSWORD_HASH` و `NOOKA_ADMIN_NAME` در نسخه ۱.۶.۱۴ دیگر برای ورود استفاده نمی‌شوند. حساب‌های اضافی را مدیر اصلی از داخل پنل ایجاد می‌کند. پس از تغییر Environment Variables، Deployment جدید لازم است.

## ۴) ساخت ادمین‌های بعدی

پس از ورود با Super Admin، در بخش «ادمین‌ها و دسترسی‌ها» ادمین جدید بسازید، رمز اولیهٔ حداقل ۱۲ نویسه و بخش‌های مجاز را تعیین کنید. رمز با Salt مستقل و scrypt هش شده و فقط Hash در Redis ذخیره می‌شود. مدیر اصلی می‌تواند مجوزها را تغییر دهد، حساب را غیرفعال یا حذف کند. حساب غیرفعال/حذف‌شده نمی‌تواند نشست قبلی خود را بازیابی کند.

مدیر اصلی از Environment Variables می‌آید و از پنل قابل حذف یا تنزل نیست. صفحهٔ قدیمی `/report.html` نیز از همین نشست Super Admin استفاده می‌کند؛ متغیر مستقل `ADMIN_TOKEN` دیگر لازم نیست و API قدیمی `/api/admin` نیز بدون نشست Super Admin درخواست را نمی‌پذیرد. دسترسی مدیریت ادمین‌ها در API فقط برای حساب Super Admin پذیرفته می‌شود.

## ۵) داده‌هایی که پنل نمایش می‌دهد

- داشبورد و گزارش پرسش‌ها: داده‌های تجمیعی `lib/report.js` در Redis.
- توکن: فقط `tokens_used` و `tokens_saved` ثبت‌شده در آمار یادگیری.
- پایگاه دانش: محتوای واقعی `knowledge/chunks.json` به‌صورت فقط‌خواندنی.
- Audit: رویدادهای واقعی ورود، خروج و عملیات مدیریت ادمین‌ها.
- زیرساخت: وضعیت اتصال Redis در همان درخواست؛ برای MySQL و Vector فقط وجود تنظیمات نشان داده می‌شود، نه سلامت تأییدشده.

## ۶) محدودیت‌های شفاف نسخه

ساختار فعلی، متن کامل هر گفتگو، تفکیک توکن ورودی/خروجی، Provider، هزینه و زمان پاسخ هر درخواست را ذخیره نمی‌کند؛ این موارد در پنل جعل یا حدس زده نمی‌شوند. گزارش پرسش‌ها تجمیعی است و پرسش‌های حساس به‌صورت متن خام ذخیره نمی‌شوند.

ویرایش و انتشار دانش در این نسخه غیرفعال است. برای فعال‌سازی امن آن باید نسخه‌بندی محتوا، اعتبارسنجی، انتشار اتمیک و همگام‌سازی Vector همراه با بازیابی در صورت خطا پیاده‌سازی شود. این عملیات عمداً به‌صورت نمایشی فعال نشده است.
