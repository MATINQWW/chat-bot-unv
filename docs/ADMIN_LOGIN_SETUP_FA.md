# راه‌اندازی ورود امن پنل نوکا — نسخه 1.6.13

این نسخه فرم ورود را روی مسیر `/admin` در Production هم نمایش می‌دهد. احراز هویت در سرور انجام می‌شود؛ هیچ حساب یا رمز پیش‌فرضی داخل ZIP وجود ندارد.

## ۱) پیش‌نیاز Redis

در Environment Variables پروژه Vercel، این دو متغیر باید در Production وجود داشته باشند و توکن باید دسترسی خواندن و نوشتن داشته باشد:

- `KV_REST_API_URL`
- `KV_REST_API_TOKEN`

توکن فقط‌خواندنی `KV_REST_API_READ_ONLY_TOKEN` برای نشست‌ها کافی نیست.

## ۲) ساخت Hash رمزها

پس از استخراج ZIP، در پوشه پروژه برای رمز Super Admin اجرا کنید:

```bash
node scripts/hash-admin-password.js
```

رمز را دو بار وارد کنید. رمز حداقل ۱۲ کاراکتر است. خروجی `scrypt$...` را کپی کنید؛ رمز خام در ترمینال نمایش داده نمی‌شود.

همین دستور را یک بار دیگر برای حساب Admin با رمز متفاوت اجرا کنید. هر دو Hash با Salt مستقل تولید می‌شوند.

## ۳) Environment Variables در Vercel

این متغیرها را در **Production** اضافه کنید:

| نام متغیر | مقدار |
|---|---|
| `NOOKA_SUPERADMIN_EMAIL` | ایمیل مدیر اصلی |
| `NOOKA_SUPERADMIN_PASSWORD_HASH` | Hash رمز مدیر اصلی |
| `NOOKA_SUPERADMIN_NAME` | نام نمایشی مدیر اصلی (اختیاری) |
| `NOOKA_ADMIN_EMAIL` | ایمیل ادمین |
| `NOOKA_ADMIN_PASSWORD_HASH` | Hash رمز ادمین |
| `NOOKA_ADMIN_NAME` | نام نمایشی ادمین (اختیاری) |

رمز خام و Hash را در GitHub، کد منبع، ZIP یا گفت‌وگو قرار ندهید. پس از تنظیم Environment Variables، Deployment جدید لازم است.

## ۴) تفاوت نقش‌ها

- **Super Admin:** داشبورد، درخواست‌ها، توکن، دانش، مدیریت ادمین‌ها، Audit و تنظیمات.
- **Admin:** داشبورد، درخواست‌ها، توکن و دانش.

حساب‌ها در این نسخه به‌صورت Bootstrap از Environment Variables خوانده می‌شوند. مدیریت دائمی چندین ادمین، تغییر مجوزها و داده‌های عملیاتی MySQL هنوز در مرحله بعدی VPS پیاده‌سازی می‌شوند.

## ۵) محدودیت فعلی پنل

ورود، نقش، نشست Redis، Rate Limit ورود و رویدادهای ورود/خروج در سمت سرور هستند. اما داده‌های داشبورد، درخواست‌ها، توکن‌ها، دانش و فهرست اعضا فعلاً نمونه‌اند؛ افزودن دانش، ساخت ادمین و تغییر مجوزها در این نسخه هنوز در دیتابیس ثبت نمی‌شود.
