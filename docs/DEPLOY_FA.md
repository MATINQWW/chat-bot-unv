# راهنمای استقرار نسخه ارتقایافته

## حالت شروع (بدون دیتابیس جدید)
1. `npm install`
2. `npm run check`
3. در Vercel متغیرهای `ICP_API_KEY`، `ADMIN_TOKEN` و `CHAT_SIGNING_SECRET` را تنظیم کنید. کلیدها فقط در محیط سرور باشند.
4. اگر rate limit و حافظهٔ مشترک بین instanceها لازم است، `UPSTASH_REDIS_REST_URL` و `UPSTASH_REDIS_REST_TOKEN` را تنظیم کنید.
5. ابتدا روی Preview deploy کنید و `/` و `/api/chat` را آزمایش کنید.

در این نسخه، ارتقای خودکار پاسخ‌های تولیدشده به حافظه پرتکرار عمداً متوقف است تا پاسخ قدیمی پس از تغییر منبع دوباره استفاده نشود. در این حالت، دانش از `data/knowledge_records_v1.jsonl` خوانده می‌شود. این فایل همراه پروژه deploy می‌شود و برای تغییر دانش باید فایل به‌روزرسانی و پروژه مجدداً deploy شود.

## حالت مدیریت زنده با Supabase (پیشنهاد برای تولید)
1. یک پروژه Supabase بسازید.
2. محتوای `docs/supabase_knowledge_schema.sql` را در SQL Editor اجرا کنید.
3. در محیط محلی، `SUPABASE_URL` و `SUPABASE_SERVICE_ROLE_KEY` را تنظیم کنید؛ سپس `npm run import:knowledge` را اجرا کنید. کلید service-role را هرگز در مرورگر یا مخزن عمومی قرار ندهید.
4. در Vercel همین متغیرها را اضافه کنید و `KNOWLEDGE_BACKEND=supabase` بگذارید.
5. ابتدا Preview deploy کنید و چند پرسش فارسی را آزمایش کنید.
6. صفحه مدیریت در `/admin.html` است. `ADMIN_TOKEN` را وارد کنید و رکوردها را یکی‌یکی بازبینی کنید. فعال‌کردن «استفاده برای ادعای رسمی» فقط وقتی مجاز است که وضعیت منبع «تأییدشده» و وضعیت زمانی «معتبر» یا «بدون نیاز به تاریخ اعتبار» باشد.

## محدودیت بازیابی
نسخه فعلی بازیابی فارسی واژه‌محور و جست‌وجوی تمام‌متنی PostgreSQL را پیاده می‌کند. هنوز embedding تولید نمی‌کند؛ برای جست‌وجوی معنایی واقعی باید یک سرویس embedding سازگار و مدل/endpoint آن جداگانه انتخاب و آزمایش شود. در مورد IranCopilot، پشتیبانی embedding را فرض نکنید تا مستندات یا تست API آن را تأیید کند.

## توجه به داده‌های اولیه
هر ۴۳۸ رکورد فعلی از خروجی پیام‌های قدیمی استخراج شده‌اند و هنوز تأیید نشده‌اند. به‌خصوص شرایط جاری پذیرش، شهریه، ظرفیت، مهلت‌ها و شماره‌های تماس باید با منبع رسمی دانشگاه راستی‌آزمایی شوند. صرف انتقال به دیتابیس آن‌ها را رسمی نمی‌کند.
