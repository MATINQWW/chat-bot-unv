# Release 1.6.4 — ادامهٔ خودکار پاسخ‌های بریده‌شده

## اصلاح اصلی

- وقتی Provider پاسخ را با `finish_reason=length` یا `max_tokens` قطع کند، بک‌اند یک درخواست ادامهٔ مستقل و کم‌حجم انجام می‌دهد.
- درخواست ادامه فقط سؤال اصلی و انتهای پاسخ قبلی را می‌فرستد؛ کل تاریخچه و دانش بازیابی‌شده دوباره ارسال نمی‌شوند.
- ادامه در پاسخ JSON و SSE پشتیبانی می‌شود.
- سقف زمانی درخواست ادامه کوتاه است و در صورت 413 فقط یک بار با ورودی و خروجی کوچک‌تر تلاش می‌شود.
- متن ادامه با هم‌پوشانی‌زدایی به پاسخ قبلی اضافه می‌شود و پاسخ نهایی دوباره امضا می‌شود.
- اگر ادامه هم کامل نشود، پاسخ به‌صراحت ناقص علامت‌گذاری متنی می‌شود و وارد حافظهٔ یادگیری نمی‌شود.

## دامنه تغییر

فقط `api/chat.js`، `lib/llm.js`، تست‌های بک‌اند، نسخه و این یادداشت انتشار تغییر کرده‌اند. فایل‌های رابط کاربری و دارایی‌های ظاهری تغییر نکرده‌اند.

## اعتبارسنجی

تست‌های شبیه‌سازی‌شده برای پاسخ JSON و SSE با `finish_reason=length` اضافه شده‌اند. پذیرش این رفتار توسط Provider واقعی پس از انتشار باید با لاگ همان Provider تأیید شود.
