# برنامه ارتقای چت‌بات دانشگاهی

## آنچه در این نسخه پیاده‌سازی شده
- انتقال ۴۳۸ رکورد ساختاریافته به `data/knowledge_records_v1.jsonl`.
- بازیابی واژه‌محور فارسی با امتیازدهی عنوان، محتوا و دسته‌بندی؛ بدون وابستگی جدید.
- حفظ شناسه منبع، دسته‌بندی، وضعیت تأیید و اعتبار زمانی در متن بازیابی‌شده.
- ارسال فراداده منابع در پاسخ `/api/chat` برای استفاده احتمالی رابط کاربری و اشکال‌زدایی.
- اصلاح سیاست مدل برای جداکردن اطلاعات دانشگاهی از راهنمایی عمومی.
- توقف ارتقای خودکار پاسخ‌های مدل به حافظه پرتکرار تا زمانی که نسخه‌بندی و ابطال کش با تغییرات زنده پایگاه دانش تضمین شود؛ این کار از ماندن پاسخ قدیمی پس از اصلاح یک منبع جلوگیری می‌کند.
- افزودن خلاصه وضعیت پایگاه دانش به خروجی پنل مدیریتی `/api/admin`.
- افزودن آزمون ساختار رکوردها و تست ابتدایی بازیابی.

## محدودیت مهم داده‌ها
تمام ۴۳۸ رکورد واردشده فعلاً `unverified` هستند و تاریخ اعتبارشان نیازمند بازبینی است. بنابراین این نسخه آن‌ها را به‌عنوان سرنخ و متن بازیابی‌شده استفاده می‌کند، نه مدرک قطعی برای مقررات رسمی. به همین دلیل شمار «منابع تأییدشده برای ادعای رسمی» فعلاً صفر است و حافظه پاسخ‌های تأییدنشده به‌صورت خودکار تقویت نمی‌شود.

## پیشنهاد ذخیره‌سازی تولیدی
- فعلاً فایل JSONL همراه کد، منبع قابل‌حمل و fallback است و برای ۴۳۸ رکورد کار می‌کند.
- برای مدیریت زنده، چند مدیر، تاریخچه تأیید و جست‌وجوی بزرگ‌تر: Supabase PostgreSQL.
- برای جست‌وجوی معنایی در مرحله بعد: `pgvector` به‌علاوه سرویس embedding سازگار. سازگاری IranCopilot با endpointهای embedding باید جداگانه تأیید شود؛ این نسخه فرض نمی‌کند که endpoint آن وجود دارد.
- Upstash Redis برای rate limit و cache مناسب است، نه منبع اصلی دانش تأییدشده.

## متغیرهای محیطی فعلی
- `ICP_API_KEY` الزامی برای پاسخ‌گویی مدل.
- `ICP_MODEL` اختیاری؛ پیش‌فرض `icp-chat`.
- `ADMIN_TOKEN` برای پنل مدیریت؛ حداقل ۱۶ کاراکتر.
- `UPSTASH_REDIS_REST_URL` و `UPSTASH_REDIS_REST_TOKEN` (یا نام‌های قدیمی `KV_REST_API_URL` و `KV_REST_API_TOKEN`) برای KV پایدار.

## چک‌لیست قبل از انتشار
1. `npm run check`
2. استقرار Preview در Vercel و آزمایش سؤال‌های واقعی فارسی.
3. بررسی اینکه IranCopilot مدل انتخاب‌شده را می‌پذیرد و `sources` در پاسخ API بازمی‌گردد.
4. تأیید دستی منابع دانشگاهی، تاریخ انتشار و اعتبار زمانی.
5. فقط پس از تأیید رکوردها، فعال‌کردن آن‌ها برای ادعاهای رسمی.
6. در مرحله بعد، ساخت جدول/پنل بازبینی در Supabase و افزودن جست‌وجوی تمام‌متنی/برداری.
