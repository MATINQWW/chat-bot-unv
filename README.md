# چت‌بات هدایت تحصیلی دانشگاه آزاد اصفهان

نسخه آماده انتشار روی **GitHub + Vercel**. ظاهر سایت و فایل‌های فرانت‌اند در این بسته تغییر نکرده‌اند.

## انتشار روی Vercel

1. محتویات این پوشه را در ریشه یک مخزن GitHub قرار دهید.
2. مخزن را در Vercel با گزینه **Add New Project → Import Git Repository** وارد کنید.
3. Framework Preset را روی **Other** بگذارید؛ Root Directory همان ریشه مخزن باشد.
4. Build Command و Output Directory را Override نکنید؛ این پروژه به Build اختصاصی نیاز ندارد.
5. در **Project → Settings → Environment Variables** متغیرهای لازم را اضافه کنید.
6. Deploy را اجرا کنید. با Pushهای بعدی به شاخه متصل‌شده، Vercel به‌صورت خودکار Deploy جدید می‌سازد.

Vercel از Node.js 26 برای Build و Functions پشتیبانی می‌کند؛ نسخه پروژه در `package.json` روی `26.x` تنظیم شده است.

## متغیرهای محیطی

فایل `.env.example` فهرست متغیرها را بدون هیچ مقدار محرمانه نشان می‌دهد. حداقل متغیر لازم برای پاسخ‌گویی مدل پیش‌فرض:

- `ICP_API_KEY`

برای امضای مطمئن شناسه‌های حافظه، `CHAT_SIGNING_SECRET` را با یک مقدار تصادفی قوی تنظیم کنید. برای محدودیت درخواست و حافظه مشترک بین Instanceهای Serverless، اتصال Upstash Redis را نیز تنظیم کنید:

- `UPSTASH_REDIS_REST_URL`
- `UPSTASH_REDIS_REST_TOKEN`

برای انتشار عمومی روی Vercel، پس از تنظیم و آزمایش Redis مشترک، متغیر `RATE_LIMIT_FAIL_CLOSED=1` را نیز در Environment Variables قرار دهید. در این حالت اگر Redis در دسترس نباشد، درخواست‌ها رد می‌شوند؛ بدون این تنظیم، شمارندهٔ محلی هر Function جایگزین می‌شود و Rate Limit بین Instanceهای Serverless سراسری نخواهد بود.

`ADMIN_TOKEN` برای صفحه گزارش در `/report.html` اختیاری است. کلیدهای Vector، Webhook و Transcription فقط در صورت فعال‌سازی قابلیت مربوط لازم‌اند.

**هیچ‌وقت `.env`، کلید API یا رمز واقعی را در GitHub Commit نکنید.**

## GitHub Actions

Workflow موجود در `.github/workflows/ingest.yml` روی Push به `main` و Pull Request اجرا می‌شود و تست‌های سرور، امنیت، منطق و ارزیابی بازیابی دانش را انجام می‌دهد.

برای همگام‌سازی خودکار Upstash Vector، این دو Secret را در GitHub → Settings → Secrets and variables → Actions تعریف کنید:

- `UPSTASH_VECTOR_REST_URL`
- `UPSTASH_VECTOR_REST_TOKEN`

بدون این Secrets، مرحله همگام‌سازی Vector اجرا نمی‌شود.

## ساختار پروژه

- ریشهٔ پروژه (فایل‌های سایت):
  - `index.html`, `style.css`, `script.js`, `owl.png`, `assets/owl/`: رابط کاربری چت و تصاویر
  - `report.html`, `report.js`: صفحه گزارش مدیریتی (با `ADMIN_TOKEN`)
  - `admin/`: رابط پنل مدیریت (`/admin`) — فقط HTML/CSS/JS؛ ورود و نقش‌ها سمت سرور در `api/admin-auth.js` انجام می‌شود
- `api/`: فقط توابع Serverless (نقاط پایانی): `chat`, `auth`, `lead`, `feedback`, `transcribe`, `admin` (گزارش با توکن), `admin-auth` (ورود پنل)
- `lib/`: منطق چت، مدل، دانش، ذخیره‌سازی و گزارش
- `knowledge/chunks.json`: پایگاه دانش بات؛ در مسیر عمومی مسدود شده و برای Functionها بسته‌بندی می‌شود. `knowledge/knowledge.txt` متن مرجع اولیه است و در کد استفاده نمی‌شود
- `config.js`: تنظیمات غیرمحرمانه پروژه (از جمله بخش `llm`)؛ کلید واقعی را فقط در Environment Variables بگذارید
- `server.js`, `deploy/`: اجرای مستقل روی VPS
- `test/`, `scripts/`, `eval/`: تست و ابزارهای توسعه که از بسته ارسالی به Vercel کنار گذاشته شده‌اند
- `docs/`: مستندات، نقشه راه، گزارش‌های امنیتی و `release-notes/`

## سیاست پاسخ‌گویی تحصیلی (نسخه 1.6.3 و بالاتر)

لایه `lib/intent.js` هر پرسش را پیش از فراخوانی مدل در یکی از سه حالت قرار می‌دهد:

- `general`: راهنمایی عمومی درباره رشته، مهارت، تناسب فردی و مسیر شغلی؛ حتی اگر پایگاه دانش اطلاعاتی نداشته باشد، مدل باید پاسخ عمومی مفید بدهد.
- `university`: اطلاعات وابسته به دانشگاه مانند شهریه، ظرفیت، تقویم، مدارک، پذیرش و خدمات؛ فقط اطلاعات مرجع برای این ادعاها معتبر است.
- `mixed`: پاسخ عمومی ارائه می‌شود و بخش اختصاصی دانشگاه جداگانه و بدون حدس بیان می‌شود.

پرسش‌های عمومی از حافظه پاسخ‌های یادگرفته‌شده خوانده یا در آن ذخیره نمی‌شوند تا پاسخ قدیمی یا تأییدنشده به‌عنوان پاسخ رسمی بازپخش نشود. گزارش مدیر نیز منبع `general` را بدون نیاز به علامت ستاره در متن پاسخ ثبت می‌کند.

این تغییر ظاهر سایت، HTML، CSS، JavaScript فرانت‌اند یا قرارداد پاسخ API را تغییر نمی‌دهد.


## هویت و لحن دستیار (نسخه 1.6.8)

- نام دستیار «نوکا» است؛ در احوالپرسی اولیه خودش را کوتاه معرفی می‌کند و در هر پاسخ نامش را تکرار نمی‌کند.
- لحن فارسی گرم، دوستانه و محترمانه است؛ نه خشک و اداری و نه بیش‌ازحد خودمانی.
- اندازه پاسخ با پیچیدگی سؤال تنظیم می‌شود: پرسش ساده چند جمله، پرسش معمولی حدود ۱۱۰ تا ۱۷۰ واژه و سؤال چندبخشی حدود ۱۸۰ تا ۲۲۰ واژه؛ پاسخ مفصل فقط در صورت درخواست کاربر تا حدود ۲۶۰ واژه.
- پاسخ باید اصل مطلب را زود بگوید، از تکرار و مقدمه کلیشه‌ای دوری کند و نکته‌های ضروری را فدای کوتاهی نکند.
- این تنظیمات در لایه Prompt و پاسخ‌های آماده اعمال شده‌اند؛ رابط کاربری تغییر نکرده است.

## مدیریت پاسخ و کیفیت مشاوره (نسخه 1.6.7)

- سؤال‌های عمومی از همان درخواست نخست با Prompt مستقل و کم‌حجم پردازش می‌شوند؛ RAG دانشگاه برای سؤال عمومی اجرا نمی‌شود.
- بودجه سؤال عمومی به‌ترتیب 700، 520 و 400 توکن است و متن ارسالی نیز در هر مرحله سقف مشخص دارد.
- برای سؤال‌های رسمی/ترکیبی، Prompt پایه کوتاه‌تر شده و فقط دانش مرتبط دانشگاه ارسال می‌شود.
- در صورت `finish_reason=length`، پاسخ با درخواست‌های ادامهٔ کوچک‌تر (320 و سپس 200 توکن) تکمیل می‌شود.
- اگر ادامه ناموفق باشد، پاسخ ناقص به‌عنوان کامل علامت‌گذاری نمی‌شود و وارد حافظه یادگیری نخواهد شد.
- لاگ‌ها فقط نوع سؤال، شماره تلاش، سقف توکن و تعداد نویسه‌های ارسالی را ثبت می‌کنند؛ متن کاربر و کلیدها ثبت نمی‌شوند.
- تست Provider واقعی IranCopilot باید پس از Deploy انجام شود؛ تست‌های محلی با Provider شبیه‌سازی‌شده هستند.


## کیفیت پاسخ مشاوره عمومی (نسخه 1.6.7)

- ادعاهای مشخص درباره میزان تقاضا، حقوق، امنیت شغلی و درآمد دلاری بدون منبع معتبر و تاریخ‌دار مجاز نیستند.
- نیاز ریاضی باید متناسب با مسیر توضیح داده شود؛ بدون چارت رسمی، ترتیب ترم‌ها یا فهرست قطعی دروس ادعا نمی‌شود.
- پاسخ عمومی معمولاً 180 تا 280 واژه و در درخواست صریحاً مفصل حداکثر 350 واژه است؛ قالب باید کوتاه، خوانا و بدون پررنگ‌سازی پاراگراف کامل باشد.
- تست سیاست کیفیت پاسخ با `node test/answer-policy.js` اجرا می‌شود.


## سخت‌سازی امنیتی و تست فشار محلی (نسخه 1.6.9)

- خروجی CSV برای مقادیر ورودی کاربر در برابر Formula Injection سخت‌سازی شده است.
- پیوست با ساختار نامعتبر پیش از دریافت سقف بزرگ‌تر بدنه رد می‌شود.
- تست‌های امنیتی، سرور، سیاست پاسخ و ارزیابی دانش با `npm run test:all` اجرا می‌شوند.
- تست بار محلی با Provider ساختگی و بدون ارسال درخواست به سرویس واقعی اجرا می‌شود: `npm run test:load:local`.
- قبل از انتشار عمومی، Redis مشترک و `RATE_LIMIT_FAIL_CLOSED=1` را تنظیم کنید و سقف هم‌زمانی/هزینهٔ Provider را با محدودیت سراسری کنترل کنید.

## پنل مدیریت نوکا (1.6.13)

مسیر پنل: `/admin`

رابط پنل روی دامنه اصلی قابل مشاهده است، اما ورود فقط با احراز هویت سمت سرور انجام می‌شود. نقش‌ها از روی حساب‌های تنظیم‌شده در Environment Variables تعیین می‌شوند؛ انتخاب نقش در مرورگر یا حساب نمایشی وجود ندارد. نشست‌ها در Redis مشترک Upstash ذخیره می‌شوند و با خروج از حساب از Redis حذف می‌شوند. اگر Redis مشترک در دسترس نباشد، ورود عمداً با خطا متوقف می‌شود.

متغیرهای لازم در محیط Production و Preview:

- `NOOKA_SUPERADMIN_EMAIL`
- `NOOKA_SUPERADMIN_PASSWORD_HASH`
- `NOOKA_SUPERADMIN_NAME` (اختیاری)
- `NOOKA_ADMIN_EMAIL` (اختیاری تا زمان ساخت حساب Admin)
- `NOOKA_ADMIN_PASSWORD_HASH` (اختیاری تا زمان ساخت حساب Admin)
- `NOOKA_ADMIN_NAME` (اختیاری)

همچنین برای نشست‌ها باید `KV_REST_API_URL` و `KV_REST_API_TOKEN` با دسترسی خواندن/نوشتن Redis تنظیم باشند. از توکن فقط‌خواندنی استفاده نکنید.

برای ساخت Hash رمز عبور، در ترمینال محلی اجرا کنید:

```bash
node scripts/hash-admin-password.js
```

رمز حداقل ۱۲ کاراکتر است. اسکریپت رمز خام را نمایش نمی‌دهد و فقط Hash مبتنی بر scrypt تولید می‌کند. Hash خروجی را در متغیر مربوط به همان نقش قرار دهید. رمز خام یا Hash را در Git، ZIP عمومی، کد منبع یا پیام ارسال نکنید. پس از افزودن یا تغییر Environment Variables، Deployment جدید بسازید.

نقش `Super Admin` همه بخش‌های رابط را می‌بیند. نقش `Admin` به داشبورد، درخواست‌ها، مصرف توکن و مدیریت دانش محدود است. در این نسخه فهرست‌ها و داده‌های داخل داشبورد هنوز نمونه هستند؛ APIهای واقعی مدیریت دانش، درخواست‌ها و تغییر مجوزها به مرحله مهاجرت MySQL روی VPS تعلق دارند. کنترل‌های مربوط به داده عملیاتی نباید تا آن زمان به‌عنوان عملیات واقعی تلقی شوند.


## دیتابیس MySQL پنل ادمین (db/)

اسکیمای MySQL پنل (ادمین‌ها و نقش‌ها، نشست‌ها، ممیزی، تیکت‌ها، درخواست تماس، بک‌آپ Vector، بازخورد، گزارش‌های روزانه، تنظیمات نسخه‌دار، فهرست درخواست‌های چت) در پوشهٔ db/ است. راه‌اندازی روی VPS، وقت تهران، ساخت ادمین و اجرای تست‌ها: db/README_FA.md. این پوشه در Vercel عمومی نیست (در vercel.json مسدود شده) و پنل فعلاً به آن وصل نیست.
